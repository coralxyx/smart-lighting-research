# Kano 工作簿复现与升级计划

## 目标

在保留现有成果的前提下，先用代码复现 `Kano词对统计分析.xlsx`，再将方法升级为可解释、可配置、可复现的 Kano-inspired 需求优先级分析。后续文本语义、视觉识别与生图模块均以新版分析结果为输入之一。

## 总体流程

```text
上游标准标签表
→ Kano 工作簿复现
→ Kano-inspired 方法修正
→ 文本与视觉模块 1—4
→ 灯光图生成
→ Web 展示与答辩材料
```

## 第一阶段：原样复现现有工作簿

### 1. 冻结现有成果

以下文件作为只读基线，不直接覆盖：

- `打tag结果(包括情感).xlsx`
- `Kano词对统计分析.xlsx`

复现结果写入新的生成目录，例如：

```text
analysis/generated/kano-reproduced.xlsx
```

### 2. 审计数据与工作簿

逐项确认：

- 输入表的字段、记录数、唯一帖子数和缺失值；
- 各工作表的数据来源与分组方式；
- 正向、中性、负向的计数与比例公式；
- A、O、I、M 分类规则和最低样本量；
- 全局汇总与分场景汇总之间的关系；
- 工作簿中的公式、隐藏区域、合并单元格和人工填写内容。

### 3. 编写复现程序

计划采用以下结构：

```text
src/kano/
├── input.py
├── aggregate.py
├── classify.py
├── bootstrap.py
└── workbook.py

scripts/run_kano.py
config/kano_inspired_v1.json
```

程序需要保留数据清洗、聚合、分类和工作簿生成的完整参数，并支持一条命令重新执行。

### 4. 复现验收

比较原工作簿与脚本生成结果中的：

- 总记录数；
- 各场景记录数；
- 各词对出现次数；
- 正向、中性、负向数量及比例；
- A、O、I、M 分类；
- 全局排序。

复现结果增加“复现对照”表，记录原值、复现值、差异和差异原因。只有差异能够解释，第一阶段才算完成。

## 第二阶段：Kano-inspired v2

### 1. 方法命名

统一使用：

> 基于 UGC 情感分布的 Kano-inspired 需求优先级分析

该方法借用 Kano 的需求类型思想，但输入是 UGC 情感数据，不等同于经典 Kano 正反问题问卷。

### 2. 分类规则配置化

将最低样本量、情感阈值、类型规则、冲突处理方式和随机种子保存到版本化配置文件，不在代码中隐式写死。

### 3. 多级统计

同时报告：

- 三元组级比例；
- 帖子级比例；
- 作者级比例（仅在存在可靠作者标识时生成）。

主结果优先采用帖子级统计，三元组级结果作为旧方法对照。

### 4. 重复与冲突处理

同一帖子中的相同场景—指标—感受组合原则上只计一次。若同一帖子对同一组合包含不同情感，处理规则必须配置化并写入方法说明。

### 5. Bootstrap 置信区间

以帖子为单位进行 bootstrap 重采样，默认重复 1000 次，输出情感比例的 95% 置信区间以及分类稳定率。若作者标识可靠，可进一步使用作者级聚类重采样。

### 6. 数据质量标记

标记样本量不足、置信区间过宽、分类不稳定、单帖主导、缺少帖子标识和缺少作者标识等问题。

## 第三阶段：新版工作簿

新版工作簿建议保存为：

```text
analysis/generated/kano-inspired-v2.xlsx
```

计划包含：

- 方法与参数；
- 数据质量；
- 复现对照；
- 词对明细_三元组级；
- 词对明细_帖子级；
- 词对明细_作者级（条件生成）；
- 场景汇总；
- 全局统计；
- 稳定性分析；
- 来源说明。

## 第四阶段：技术模块 1—4

### 模块 1：文本语义聚类

保留 TF-IDF 作为 baseline，加入 Sentence Transformer，并比较聚类数量、噪声率、内部评价指标和人工一致性。

### 模块 2：YOLO 目标检测

先完成预训练模型的家具检测 baseline，再建立灯具类别标注规范并进行迁移学习。目标类别包括吊灯、台灯、落地灯、灯带和射灯等。

### 模块 3：光照区域分割

提取发光区、受光区、亮区和阴影区，计算明暗比例、局部对比度、光源集中程度和空间光照层次。后续可接入 MobileSAM 精修。

### 模块 4：美学属性识别

建立底图标注模板，以 OpenCLIP 零样本识别作为 baseline；有足够人工标签后训练线性分类器，预测暖色、柔和、间接照明、层次丰富等属性。

## 第五阶段：生图与 Web

```text
用户上传室内图
→ 识别空间、家具与灯具
→ 提取光照和美学特征
→ 用户选择目标感受
→ 检索 Kano/知识映射
→ 生成设计参数与灯光图
→ 展示前后对比及设计解释
```

Web 是展示和交互层，在数据、统计方法及视觉模块稳定后实现。
